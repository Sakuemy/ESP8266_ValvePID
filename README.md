# ESP8266 — ПИД-регулятор крана по DS18B20

Скетч для ESP8266, управляющий сервоприводом шарового крана по показаниям
датчика DS18B20 через ПИД-регулятор. Включает веб-интерфейс (мониторинг +
настройки), локальное меню на OLED/энкодере, NTP-синхронизацию времени и
хранение настроек в LittleFS.

## Структура проекта

| Файл | Назначение |
|---|---|
| `ESP8266_ValvePID.ino` | `setup()`/`loop()`, связывает модули между собой |
| `Config.h` | Пины, константы, структуры настроек |
| `Storage.*` | Загрузка/сохранение настроек в LittleFS (JSON) |
| `TempSensor.*` | Неблокирующее чтение DS18B20 |
| `PIDController.*` | Собственный ПИД с anti-windup |
| `ValveServo.*` | Управление сервоприводом, лимиты открытия |
| `TempHistory.*` | Кольцевой буфер истории температуры (RAM, 24ч) |
| `TimeManager.*` | NTP + оффлайн-фолбэк по millis() |
| `NetworkManager.*` | Подключение Wi-Fi (DHCP/статика), AP-фолбэк |
| `WebServerManager.*` | HTTP-сервер: дашборд, настройки, JSON API |
| `DisplayMenu.*` | Меню на OLED + энкодере |
| `BatteryMonitor.*` | Измерение заряда батареи через АЦП (A0), калибровка 0%/100% |

## Необходимые библиотеки (Arduino Library Manager)

- **OneWire**
- **DallasTemperature**
- **ArduinoJson** (v6.x)
- **U8g2**

`Servo`, `ESP8266WiFi`, `ESP8266WebServer`, `LittleFS` идут в комплекте
с ESP8266 core for Arduino (устанавливается через Boards Manager,
URL пакета: `http://arduino.esp8266.com/stable/package_esp8266com_index.json`).

**Важно:** во вкладке Tools → Flash Size выберите вариант с разделом LittleFS
(например, "4MB (FS:1MB)"), иначе `LittleFS.begin()` не найдёт файловую систему.

## Схема подключения (пины по умолчанию, см. `Config.h`)

Прошивка настроена под **NodeMCU ESP8266 V3 со встроенным OLED-дисплеем**
(модули вида GREATZT и аналогичные) — на таких платах I2C дисплея уже
распаян производителем на D5/D6 (не на "стандартных" для ESP8266 D1/D2),
причём **SCL = D6 (GPIO12), SDA = D5 (GPIO14)** — именно так подписывает
сама заводская демо-прошивка платы на экране при первом включении. Учтите,
что в Arduino-ядре ESP8266 константы D5/D6 определены "не интуитивно":
`D5 = GPIO14`, `D6 = GPIO12` — легко перепутать, какая из них SCL, а
какая SDA. DS18B20 и сервопривод разведены на D1/D2 (они освободились),
чтобы не конфликтовать со встроенным дисплеем:

| Устройство | Пин ESP8266 (NodeMCU) |
|---|---|
| DS18B20 (DQ, через резистор 4.7кОм к VCC) | D1 (GPIO5) |
| Сервопривод (сигнал) | D2 (GPIO4) |
| OLED SSD1306 (встроенный), SCL | D6 (GPIO12) |
| OLED SSD1306 (встроенный), SDA | D5 (GPIO14) |
| Энкодер CLK | D7 (GPIO13) |
| Энкодер DT | D8 (GPIO15) |
| Энкодер SW (кнопка) | D0 (GPIO16) |
| Батарея (через делитель напряжения) | A0 |

**Если у вас дисплей на других пинах** (внешний модуль, а не встроенный,
или другая ревизия платы) — поправьте `PIN_OLED_SDA`/`PIN_OLED_SCL` в
`Config.h` под свою разводку.

**Примечание по strapping-пинам:** GPIO0, GPIO2 и GPIO15 участвуют в выборе
режима загрузки ESP8266. D8/GPIO15 (энкодер DT) в штатной работе — просто
цифровой вход с `INPUT_PULLUP`, но если ваша плата держит на нём внешнюю
подтяжку к VCC (как это иногда сделано на модулях), при старте могут быть
проблемы с загрузкой. Если увидите нестабильный boot — перенесите DT на
другой свободный пин (например, RX/GPIO3, если не используете `Serial`
для отладки) и поправьте `PIN_ENC_DT` в `Config.h`.

GPIO16 (D0) не поддерживает аппаратные прерывания и `PULLUP` в некоторых
ревизиях — кнопка энкодера читается поллингом в `DisplayMenu.cpp`, отдельная
подтяжка не обязательна, но резистор 10 кОм к GND на всякий случай не
помешает, если кнопка "дребезжит".

## Батарея

Устройство измеряет напряжение на пине **A0** и переводит его в % заряда
по двум калибровочным точкам, которые задаются в веб-интерфейсе
(`/settings`) или через меню на дисплее: "напряжение при 0%" и
"напряжение при 100%" (например, для одной ячейки Li-ion — 3.0В и 4.2В).

- Если у вас батарея с напряжением выше, чем позволяет измерить A0
  напрямую (для NodeMCU/Wemos со встроенным делителем — это 0..3.3В),
  добавьте свой резистивный делитель между плюсом батареи и GND, а
  среднюю точку подайте на A0:

  ```
  Батарея (+) ---[ R1 ]---+---[ R2 ]--- GND
                          |
                          A0
  ```

  Коэффициент делителя `ratio = (R1 + R2) / R2` задайте в поле
  **"Коэффициент делителя (A0)"** — в веб-интерфейсе (`/settings` →
  карточка "Батарея") или в меню на дисплее ("Батарея: коэф.
  делителя"). Значение хранится в настройках и применяется сразу, без
  перепрошивки. Например, для батареи 2S Li-ion (до ~8.4В) при
  R1=100кОм, R2=47кОм: ratio = (100+47)/47 ≈ 3.13.
  Калибровочные точки 0%/100% в веб-интерфейсе при этом задаются в
  реальных вольтах батареи (уже после учёта делителя).
  По умолчанию (без внешнего делителя) ratio = 1.0.
- Если измеренное (пересчитанное) напряжение ниже
  `BATTERY_DISCONNECT_THRESHOLD_V` (по умолчанию 1.0В в `Config.h`),
  устройство считает, что батарея физически не подключена, и помечает
  это отдельным статусом как на дашборде, так и в меню дисплея, вместо
  того чтобы показывать бессмысленный % заряда.

## Доступ к настройкам по паролю

Страница `/settings` и все `/api/settings/*` (веб) и пункты редактирования
в меню на дисплее (всё, кроме просмотра температуры/IP/батареи) требуют
пароль. Дашборд-мониторинг (`/`, `/api/status`, `/api/history`) остаётся
открытым, чтобы график и текущие показания были доступны без входа.

- **Веб**: обычная HTTP Basic Auth — браузер сам покажет диалог
  логин/пароль при заходе на `/settings`. Логин фиксирован: `admin`.
- **Дисплей**: при попытке зайти в любой пункт меню, кроме первых трёх
  (просмотр), устройство попросит ввести пароль посимвольно тем же
  способом, что и SSID (вращение энкодера выбирает символ, клик —
  подтверждает символ, долгое удержание — подтверждает весь пароль).
  Символы пароля показываются звёздочками. После успешного ввода меню
  остаётся разблокированным `MENU_LOCK_TIMEOUT_MS` (по умолчанию 2
  минуты) бездействия, затем блокируется снова автоматически.
- **Пароль по умолчанию**: `admin` (константа `DEFAULT_ADMIN_PASSWORD`
  в `Config.h`). **Смените его при первом запуске** — как и пароль
  AP-точки `ValvePID-Setup`.
- **Смена пароля**: в веб-интерфейсе — карточка "Безопасность" на
  `/settings` (нужно ввести текущий пароль + новый дважды); на дисплее —
  пункт меню "Сменить пароль" (доступен после разблокировки текущим
  паролем). Минимальная длина нового пароля — 4 символа.
- Это HTTP Basic Auth без TLS (ESP8266 практически не тянет HTTPS с
  разумной производительностью) — пароль передаётся по локальной сети
  не в зашифрованном виде. Это защита от случайного/любопытного доступа
  в общей Wi-Fi сети или с устройства, оказавшегося рядом физически, а
  не криптографическая защита от перехвата трафика — не используйте тот
  же пароль, что и для более критичных сервисов.

## Веб-интерфейс — полностью локальный

Дашборд и страница настроек не используют внешние CDN, шрифты или
скрипты — вся разметка, стили и JavaScript (включая отрисовку графика
на `<canvas>`) отдаются самим устройством и хранятся во флеш-памяти
(PROGMEM). Открытие интерфейса и его работа не требуют подключения к
интернету — доступ в сеть нужен только для NTP-синхронизации времени,
и его отсутствие не мешает мониторингу/настройке через локальную сеть.

## Первый запуск

1. Если в `settings.network.ssid` пусто (первая прошивка), устройство
   поднимет точку доступа `ValvePID-Setup` (пароль `12345678`).
2. Подключитесь к ней и откройте `http://192.168.4.1/settings`.
3. Укажите SSID/пароль вашей сети и режим получения IP, сохраните.
4. Устройство переподключится к указанной сети без перепрошивки.

При наличии сохранённых настроек устройство при каждом включении
автоматически пытается подключиться к сохранённой сети; при временной
недоступности сети продолжает работать в обычном режиме (кран управляется
по ПИД независимо от состояния Wi-Fi), периодически повторяя попытки
подключения в фоне.

## Если экран не работает

Строки CLK/DT/SW читаются поллингом, а не по прерыванию, поэтому
проблемы с дисплеем и с энкодером — разные вещи и диагностируются
раздельно:

1. Откройте Serial-монитор (115200 бод) и перезагрузите плату. При
   старте `DisplayMenu::begin()` печатает, отозвался ли дисплей на
   I2C-транзакцию:
   - `[Display] OLED инициализирован` — прошивка достучалась до экрана,
     если картинки всё равно не видно — проверьте контрастность/питание
     самого модуля или что это правда SSD1306 (а не SH1106 — у него
     другой драйвер и с этим `U8g2` конструктором работать не будет).
   - `[Display] u8g2.begin() не подтвердил инициализацию` — I2C не
     видит устройство. Проверьте по порядку:
     - Питание модуля (3.3В и GND) и что провода не перепутаны местами
       (SDA/SCL часто путают на дешёвых модулях).
     - Подключение `SDA -> D5 (GPIO14)`, `SCL -> D6 (GPIO12)` (см. таблицу
       пинов выше) — переставлены не туда или перепутаны местами SDA/SCL -
       самая частая причина (в Arduino-ядре ESP8266 константы D5/D6
       определены "не интуитивно": D5=GPIO14, D6=GPIO12).
     - Адрес I2C: код использует адрес по умолчанию для варианта
       `SSD1306_128X64_NONAME` (0x3C). Часть модулей распаяна на 0x3D —
       в этом случае конструктор в `DisplayMenu.cpp` нужно заменить на
       вариант с явным адресом, либо перепаять адресный резистор на
       модуле, если это предусмотрено.
     - Что это действительно 128x64 (а не 128x32) — иначе изображение
       будет как минимум искажено, а с некоторыми клонами дисплей может
       и вовсе не отвечать на транзакции инициализации, рассчитанные на
       другой контроллер/резолюцию.
2. Если ничего не печатается вообще (даже "[Boot]...") — проблема не в
   дисплее, а в самой прошивке/питании платы — проверьте, что скетч
   загрузился и Serial подключён к правильному COM-порту/скорости.

## Проектные решения по надёжности (узкие места из ТЗ)

- **Никаких блокирующих `delay()` в `loop()`.** Все операции (чтение
  датчика, конвертация DS18B20, обновление сервопривода, HTTP-сервер,
  энкодер) построены на неблокирующих таймерах через `millis()`.
- **DS18B20** опрашивается в режиме `setWaitForConversion(false)`:
  запрос конвертации и считывание результата разнесены по времени.
- **История температуры** держится в фиксированном кольцевом буфере
  (`HISTORY_SIZE = 288`), а не в динамически растущем контейнере —
  переполнение буфера исключено, старые точки перезаписываются.
- **Запись в LittleFS** дебаунсится (`SETTINGS_AUTOSAVE_DEBOUNCE_MS`),
  чтобы не изнашивать флеш частыми записями при пакетном изменении
  нескольких настроек подряд, и делается через временный файл +
  `rename()`, чтобы не оставить конфиг повреждённым при потере питания
  посреди записи.
- **Дребезг энкодера и кнопки гасится по времени**: оба входа читаются
  поллингом (`DisplayMenu::pollEncoder()`/`pollButton()`), изменение
  уровня принимается как достоверное, только если он удержался
  стабильным дольше `ENCODER_DEBOUNCE_MS`/`BUTTON_DEBOUNCE_MS`
  (`Config.h`) — иначе один физический щелчок/нажатие может породить
  несколько ложных срабатываний.
- **Anti-windup в ПИД**: интегральная составляющая не растёт, когда
  регулятор уже находится в насыщении (кран полностью открыт/закрыт) в
  ту же сторону, что и текущая ошибка — это предотвращает "залипание"
  и перерегулирование после длительного отклонения температуры.
- **Сервопривод обновляется не чаще `SERVO_UPDATE_INTERVAL_MS`**, чтобы
  не дёргать его на каждой мелкой флуктуации ПИД-выхода.
- **Разрыв Wi-Fi не останавливает регулирование**: `NetworkManager`
  переподключается в фоне, `TimeManager` при потере NTP переходит на
  оценку времени по `millis()` от последней успешной синхронизации.
- **Веб-страницы отдаются из PROGMEM** (`send_P`), а JSON собирается
  через `ArduinoJson` с буферами фиксированного размера (`StaticJsonDocument`)
  — исключает фрагментацию кучи от неограниченного роста `String`.

## Известные ограничения / что можно доработать

- Ввод пароля Wi-Fi через энкодер не реализован (только SSID) — пароль
  удобнее задавать через веб-форму `/settings`; на дисплее это отмечено.
- Часовой пояс в `TimeManager::begin()` захардкожен как UTC
  (`NTP_GMT_OFFSET_SEC = 0` в `Config.h`) — при необходимости смещения
  под локальное время поменяйте константу.
- Для более отзывчивого энкодера при высокой скорости вращения можно
  перейти на аппаратные прерывания (`attachInterrupt`) вместо поллинга,
  но это потребует переноса DT/CLK на пины, поддерживающие прерывания
  (все, кроме GPIO16).
